Gameshow System

Prepared by Evan Grobbelaar Date August 2026 Audience Developer / Technical Team Version 2.0
01 — Overview

What This Is

Noot-vir-Noot is a live, in-person music and general knowledge quiz show. Contestant teams sit at numbered tables. Each table has a physical button unit with four RGB-LED buttons — A, B, C, and D. A question video plays on a large screen at the front of the room. Everyone watches the same screen.

The show is run by a single operator (the host) on a laptop. The operator uses a handheld wireless clicker to control the pacing of the game. The clicker is the only thing the host needs to hold during the show.

02 — Setup

Physical Setup

  • 1–2 large displays — projector or TV at the front. Both show identical content via HDMI. Everyone — contestants and audience — watches the same screen at all times.
  • Operator laptop — the laptop screen is the private control view. The extended display(s) show the game. Connected via HDMI screen extend.
  • Up to 12 tables, each with one button unit: 4 RGB-LED buttons (A, B, C, D).
  • Teams of 2–4 people per table share one button unit. One person presses the button on behalf of the team.
  • Handheld clicker — the host's only control device. Left click = wrong, Right click / forward = correct / next. No keyboard needed during a live show.
  • All button units connect over WiFi — no cables to tables.
03 — Show Structure

How a Show Is Organised

A show consists of multiple rounds. Each round has a theme and contains several questions. Between rounds and at dramatic moments, the host toggles the big screen to show the leaderboard. The host controls all pacing — the system never advances on its own except at the end of a countdown timer.

04 — Show Flow

How a Show Runs, Start to Finish

1
Landing Screen

The big screen shows a holding visual while the venue fills up. The leaderboard can be toggled on here to show table numbers and names.

2
Intro Video

Host triggers the intro. A short energetic opener plays on the big screen. During this, all button units cycle through random colour patterns — a light show that signals the show is starting. At the end of the intro, all buttons switch off.

3
Questions (repeated per question)

See Section 05 — Question Flow for the full detail of each question.

4
Leaderboard (host's discretion)

At any point the host can toggle the big screen to show the animated leaderboard — after a question, between rounds, or to build tension. They toggle back when ready to continue.

5
Dance Breaks & Instructional Videos

Between rounds, the host can play a dance break video (audience and tables participate) or an instructional video explaining the next round's rules. These play through completely with no pauses.

6
End of Show

After all questions are done, the host triggers the final leaderboard — a full animated ranking. The winner is announced. The button units celebrate with a colour show.

05 — Question Flow

What Happens During Each Question

Every question video is made up of five segments that play in sequence. The video pauses automatically at two points — the host clicks the clicker to advance each time.

Segment 1 — Category Reveal
The screen shows the question type: AUDIO QUESTION, PHOTO QUESTION, or GENERAL KNOWLEDGE. Animated background, music. Buttons stay off.
⏸ Pause 1 — host clicks to continue
Video pauses on the category screen. Host clicks the clicker when the room is ready. Buttons go solid red — contestants see this as "not yet."
Segment 2 — Question Content (~5 s)
The actual question plays. For audio questions: a music clip. For photo: an image is revealed. For general knowledge: the question text appears. Buttons remain red — still not time to answer.
Segment 3 — Countdown (5 s, configurable)
Immediately after the question, the countdown begins with no pause in between. Two modes:

Multiple Choice: A, B, C, D option cards appear with a countdown timer. Buttons arm — each button lights its own colour. All tables press their answer simultaneously. The system records every table's choice.

Fastest Finger: A large "FASTEST FINGER!" screen with a countdown ring. No option cards. Buttons arm. The first table to press any button locks in — their table name/number flashes on the big screen. All other tables lock out.
⏸ Pause 2 — auto-pause when timer hits zero
The video pauses automatically when the countdown ends. No clicker press needed to trigger this pause.
Segment 4 — Timeout Screen
"TIME'S UP!" screen with a red flash. The video is paused here waiting for the host.

Multiple Choice: System has already recorded all answers. Host clicks the clicker to advance — points are awarded automatically as the answer reveals.

Fastest Finger: Host walks to the table that buzzed first (their name is still on screen). Host listens to their verbal answer. Host clicks RIGHT = correct or LEFT = wrong on the clicker. Points are awarded accordingly. Video then advances to the answer.
Segment 5 — Answer Reveal
The correct answer appears in a large animated card with confetti and celebration effects. For fastest finger questions, a ✓ or ✗ symbol appears at the bottom-left of the screen showing whether the buzzing table answered correctly or not. Button LEDs on each table show green (correct) or red (wrong) based on what they pressed.
Dynamic timing: Each question video has its own pause timestamps baked in. This means different questions can have different countdown lengths (e.g. 5 seconds for a quick round, 10 seconds for a harder question) and the player always pauses at exactly the right moment.

07 — Screen

What the Big Screen Shows

The big screen is always in one of three states. The host toggles between them using the clicker or control panel.

Game Video
Full-screen pre-produced video playing the current question or content. All timing, graphics, music, and text come from the video itself — the host does not manage what appears on screen during a question.
When
During every question segment
Leaderboard
Animated full-screen ranking. All tables shown with scores, sorted highest first. Positions animate smoothly as scores change. The audience can follow the competition in real time.
When
Host toggles manually at any moment
Landing / Holding
A visually appealing idle screen shown before the show starts and between major sections. Show branding or a pre-show countdown.
When
Before show starts, at host's discretion

During a fastest finger question, when a table buzzes in, their table name/number appears prominently on the big screen — so the whole room knows who buzzed first. This overlay stays visible through the timeout screen while the host walks over to hear their answer.

10 — Operator

The Host's Experience

The host runs the entire show from one laptop using a single handheld wireless clicker:

  • Right click / forward — advance to next state (NEXT), or mark fastest-finger answer as correct
  • Left click / back — mark fastest-finger answer as wrong
  • The laptop screen shows a private control panel: table connection status, answers received, current game state, and the leaderboard toggle
The host must never need to touch the keyboard during a live show. The system should be invisible — it just works. Reliability and simplicity come before every feature.
11 — Tooling

Question Video Generator

All question videos are prepared in advance by the host using a desktop tool called the Question Editor (question_editor.py). No video editing software is needed.

For each question, the host enters:

  • Question type: Multiple Choice or Fastest Finger
  • Media type: Text, Photo, or Audio
  • The question text and (for MC) four answer options with the correct answer marked
  • Optional: a photo or audio file to embed in the video
  • Countdown duration (default 5 seconds, adjustable per question)
  • Background music and sound effects (intro jingle, countdown tick, timeout ding)

The tool generates a fully animated MP4 video for each question — with all five segments, animated backgrounds, a countdown ring, confetti on the answer reveal, and any embedded media — and saves it directly to the correct folder.

Each generated video also produces a small sidecar metadata file (.meta.json) that tells the game player exactly when to pause for that specific video — so longer or shorter countdowns are handled automatically without any manual configuration.

The developer should note: the game player (video_player.py) needs to be updated to read each video's .meta.json sidecar for its pause timestamps, rather than using the current global config timing values.
